WADIDAW — SATURATION / CLIPPER
MASTER PROJECT SPECIFICATION FOR CODEX
=======================================

PROJECT GOAL
------------
Build the WADIDAW Saturation / Clipper plugin end-to-end as a real, functional VST3 audio plugin.

The plugin is an audio effect focused on:
1. Soft clipping / clipping control
2. Harmonic drive / saturation
3. Anti-aliasing through oversampling
4. Professional real-time metering and visualization
5. A rugged vintage/industrial studio-rack interface

IMPORTANT:
This document is the engineering source of truth.
A visual reference image will also be provided to Codex. Use the image as the UI/visual reference, but do NOT replace real DSP or functionality with fake/static UI behavior.

The final product must be a real usable plugin, not a mockup.

DRIVE DSP
---------
The three drive modes must sound meaningfully different.

GROWL:
- Dense harmonic saturation
- Stronger harmonic weight
- Aggressive character

ODD:
- More pronounced odd harmonics
- Edgier / more forward distortion character

TAPE:
- Smoother saturation
- Warmth
- Mild compression / softening behavior

The implementation can use appropriate waveshaping, nonlinear processing, filtering, saturation stages, or other DSP techniques.

Avoid simply changing gain and calling it three different modes.

Mix must provide real dry/wet blending.

Character must alter the tonal / nonlinear character in a meaningful way.

HPF and LPF must be real filters in the drive path.

DSP / REAL-TIME SAFETY
----------------------
Audio processing must be suitable for real-time use.

Do NOT:
- Allocate memory in the audio callback
- Perform blocking operations in the audio callback
- Perform filesystem access in the audio callback
- Perform UI operations in the audio callback
- Perform expensive dynamic work unnecessarily

Use safe parameter communication between UI and DSP.

Preallocate buffers where possible.

Keep meter/history communication thread-safe.


MULTI MODE DETAILS
------------------
STEREO:
Process normal L/R stereo signal.

M/S:
Process Mid/Side appropriately.
Convert L/R -> M/S.
Process.
Convert M/S -> L/R.

MULTI BAND:
Implement a sensible multi-band processing architecture.

If a complete multi-band implementation is too invasive for the existing architecture, first establish a clean extensible architecture and implement a stable minimum viable multi-band mode rather than faking the feature.

No fake controls.

- 2x
- 4x
- 8x

CPU / PERFORMANCE
-----------------
Keep CPU usage reasonable.

Avoid unnecessary redraws.

Do not redraw large visualizations at audio rate.

Separate:
- Audio processing rate
- Meter update rate
- UI repaint rate

Target a responsive UI without wasting CPU.
